### 2、SerialPort的基本属性参数

基本参数来源于设备方提供的参数，两方接口必须得对上

```c#
using System.IO.Ports;

namespace SerialPort实践
{
    internal class Program
    {
        static void Main(string[] args)
        {
            // 对象的静态方法，不需要实例化直接调用
            // 获取当前环境下所有的有效接口名称
            SerialPort[] ports = SerialPort.GetPortNames();
            SerialPort serialPort = new SerialPort();
            // 串口通信
            // 指定通信的串口名称
            serialPort.PortName = "COM1";  //假设我要和COM1通信
            //波特率（串口通信速率，物理接口以什么样的频率发送信号）
            serialPort.BaudRate = 9600;
            //数据位（每个数据的有效位数，单位比特）
            serialPort.DataBits = 8;
            //校验位（用于错误检测，常用无校验）
            serialPort.Parity = Parity.None;
            //停止位（用于数据帧结束标志，一般 1 位）
            serialPort.StopBits = StopBits.One;

            //也可以在定义对象的时候直接填入（注意要和厂家提供的顺序一致）
            SerialPort serialPort2 = new SerialPort("COM1",9600,Parity.None,8,StopBits.One);
        }
    }
}
```

### 5、串口的接收

```c#
static void SendAndReceive(SerialPort serialPort) //封装一下中文的发送方法
{
    //发送数据
    string str = "这是中文";
    byte[] bytes = Encoding.UTF8.GetBytes(str);
    serialPort.Write(bytes, 0, bytes.Length);
    //接收ASCII数据（读取缓冲区已经存在的数据，缓冲区为空就跳过，这个不卡线程）
    string rec_str = serialPort.ReadExisting();//仅仅支持ASCII码格式
    //接收字节流的数据（支持中文）
    byte[] rec_bytes = new byte[10];
    serialPort.Read(rec_bytes, 0, rec_bytes.Length);
}
```

### 6、事件驱动型通信DataReceived

上面那些传统的通信方式都是通过轮询来实现的，这种方法占用CPU过大，卡界面

```c#
while(true)
{
    if(serialPort.BytesToRead > 0)
    {
        读数据...
    }
}
```

如果使用事件驱动性通信，串口自己监控数据，一旦收到数据，系统自动触发 DataReceived 事件，只需要写收到数据后要干嘛的代码就行。<br>
这种通信方式不占 CPU，界面流畅，符合工业标准<br>

DataReceived是一个委托事件，当串口接收缓冲区有新数据时，.NET 框架自动调用绑定的方法

```c#
// 1. 创建串口对象
SerialPort serialPort = new SerialPort();

// 2. 配置四参数
serialPort.PortName = "COM3";
serialPort.BaudRate = 115200;
serialPort.DataBits = 8;
serialPort.Parity = Parity.None;
serialPort.StopBits = StopBits.One;

// 3. 绑定 DataReceived 事件（关键！）
serialPort.DataReceived += SerialPort_DataReceived;

// 4. 打开串口
serialPort.Open();
```

```c#
private void SerialPort_DataReceived(object sender, SerialDataReceivedEventArgs e)
{
    SerialPort sp = (SerialPort)sender;
    
    // 读取数据
    string receivedData = sp.ReadExisting();

    // 这里处理数据：解析、显示、存库...
    Console.WriteLine("收到数据：" + receivedData);
}
```

注意在使用这个方法时需要保障线程安全，因为DataReceived事件在非UI线程触发，需要通过Invoke来更新界面，还要注意资源的释放（使用括号using或者try finally确保串口关闭），还要及时读取数据，避免缓冲区溢出。





## 二、Modbus协议

Modbus是一种由施耐德电气于1979年推出的串行通信协议，最初设计用于可编程逻辑控制器(PLC)间的通信。<br>
作为工业自动化领域的事实标准，Modbus已成为电子设备间最常用的连接协议之一。协议最初基于RS-232串行总线(点对点通信)，后扩展支持RS-485(多点通信)。随着工业以太网发展，Modbus衍生出面向TCP/IP网络的Modbus TCP变体，同时保留了Modbus RTU(二进制高效传输)和ModbusASCII(可读文本格式)两种串行通信模式。

当然上面的读取方式会卡住线程页面，如果时间过长就很不好了，此时可以使用异步多线程，用自带的masert.ReadHoldingRegistersAsync方法实现，注意这个方法的返回值是Task类型对象。

```c#
static void Main(string[] args)
{
    SerialPort serialPort = new SerialPort("COM1",9600,Parity.None,8,StopBits.One);
    serialPort.Open();
    //创建ModbusRTU的通信协议对象
    IModbusSerialMaster masert = ModbusSerialMaster.CreateRtu(serialPort);
    masert.Transport.ReadTimeout = 2000;  //读超时
    masert.Transport.Retries = 3;         //重试次数

    ushort[] register = masert.ReadHoldingRegisters(5, 0, 10);
    Task<ushort[]> result =  masert.ReadHoldingRegistersAsync(5, 0, 10);
    register = result.GetAwaiter().GetResult();
    serialPort.Close();
}
```

还有一种封装成单独方法的await方式，加个await前缀可以让返回值从Task类型转换为ushort[]类型，使得ushort[] register可以直接接收，方法名会自动加上async



OK读取数据会了，现在尝试着向从机写数据，前面我们知道输入线圈和输入寄存器是只读的，因此只能写线圈状态和保持寄存器


```c#
private static void NModbus4Test()
{
    SerialPort serialPort = new SerialPort("COM1", 9600, Parity.None, 8, StopBits.One);
    serialPort.Open();
    //创建ModbusRTU的通信协议对象
    IModbusSerialMaster masert = ModbusSerialMaster.CreateRtu(serialPort);
    masert.Transport.ReadTimeout = 2000;  //读超时
    masert.Transport.Retries = 3;         //重试次数

    //向从站5的寄存器5地址里面写入1234（单写）
    masert.WriteSingleRegister(
        slaveAddress:5,
        registerAddress:5,
        value: 1234
    );

    //向从站5的寄存器0地址,1地址,2地址中依次写入三个数据（多写）
    ushort[] value = { 100, 200, 300 ,400};
    masert.WriteMultipleRegisters(5,0,value);  //从站地址、起始地址、值（数组长度决定写到哪）

    serialPort.Close();
}
```

如果每个寄存器的单元占用2个字节，那么可以使用ushort类型，范围是（0-65535），如果是short则是（-32768-32767）范围，如果占用1个字节，就可以用byte（0-255），和sbyte（-256-255）。<br>
如果是4个字节，可以使用int_32和uint_32和float。<br>
如果寄存器一个地址是2字节，但是我的数据是4字节长度的float怎么办？可以将其按照字节进行拆分，拆分成一个单元2字节的数组，可以参考以下转换代码

```c#
float v7 = 4.5f;  //4字节大小
ushort[] datas = new ushort[2];  //可以拆分为2个ushort类型
//获取浮点型数字对应的字节信息
byte[] v7_bytes = BitConverter.GetBytes(v7);
//注意大小端字节序，假设数值300转换为16位二进制再存入内存中是0x01 Ox2C
// 大端顺序（高位在前低位在后）
datas[0] = 0x01;
datas[1] = 0x2C;
// 小端顺序（高位在后低位在前）
datas[0] = 0x2C;
datas[1] = 0x01;
//在Modbus协议中大部分都是使用大端顺序存储的，以设备方的设备为准
```

拆分可以参考以下方式：

```c#
//向从站5的寄存器0地址,1地址,2地址中依次写入三个数据（多写）
ushort[] value = { 100, 200, 300 ,400};
masert.WriteMultipleRegisters(5,0,value);  //从站地址、起始地址、值（数组长度决定写到哪）
float v7 = 4.5f;  //4字节大小
ushort[] datas = new ushort[2];  //可以拆分为2个ushort类型
//获取浮点型数字对应的字节信息
byte[] v7_bytes = BitConverter.GetBytes(v7);
//手动大端转 ushort,v7_bytes[0]是高8位，v7_bytes[1]是低8位。高8位左移8位（等价 * 256）+低8位，拼成16位整数
ushort s1 = (ushort)(v7_bytes[0] * 256 + v7_bytes[1]);
//调用API来实现小端转ushort，所以是先v7_bytes[1]后v7_bytes[0]
s1 = BitConverter.ToUInt16(new byte[] { v7_bytes[1],v7_bytes[0]}); 
//s2同理
ushort s2 = (ushort)(v7_bytes[2] * 256 + v7_bytes[3]);
s1 = BitConverter.ToUInt16(new byte[] { v7_bytes[3], v7_bytes[2] });
datas[0]= s1;
datas[1] = s2;
masert.WriteMultipleRegisters(5,8,datas);
```

写入保持寄存器的教程到此为止，接下来是写入线圈状态的方法，由于线圈状态是由二进制（true和false）表示，因此只需以比特为单位来写

```c#
//向从站2的0号线圈写入true状态
masert.WriteSingleCoil(2, 0, true);
//向从站1的5号线圈开始连续写入5个状态
masert.WriteMultipleCoils(2,5,new bool[] {true,false,true,true,false});
```
